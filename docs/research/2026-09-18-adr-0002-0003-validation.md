## 1. D-CFR justification

**What the cited source claims.** Wu et al., *CSI-Based Indoor Localization*,
TPDS 24(7), doi:10.1109/TPDS.2012.214 (FILA) never differences subcarriers.
Its fingerprint is "normalized CSI values at each subcarrier for each AP",
normalized so they "reflect the combination result ignoring the large scale
fading" (§5.1), plus a weighted-average "effective CSI" for ranging (Eq. 4).
Similarity is the product over K APs of the Pearson correlation of the
normalized spectra (Eq. 10), used as the location prior (Eq. 11). So FILA
supports *normalization + Pearson*, not differencing; `\cite{wu2012csi}` on
the D-CFR sentence in `methodology.tex` §sec:dcfr over-attributes. No primary
paper introducing "differential CFR" on amplitudes was found; the differencing
idea in the CSI literature is applied to *phase* between adjacent subcarriers
or antennas to cancel CFO/SFO-induced offsets (secondary: Ma, Zhou, Wang,
*WiFi Sensing with CSI: A Survey*, ACM CSUR 2019, doi:10.1145/3310194). CFO
and SFO are phase terms; they do not touch amplitude, so the ADR is right to
drop the CFO/SFO claim.

**Does amplitude differencing cancel tilt?** Write
`|H_k| = s·(c + t·k + m_k)` (AGC scale `s`, offset `c`, linear tilt `t`,
multipath `m_k`). After L2 normalization (`gateway/csi.py: normalize`) and
`np.diff` (`dcfr`): `Δ_k ∝ t + (m_{k+1} − m_k)`. The offset `c` is removed
exactly; the tilt `t` becomes a *constant* added to every element, not
removed. Pearson ρ is invariant to affine changes of either vector, so the
Sniper never sees `t`; the k-NN baseline (Euclidean on the concatenated
vector) does. Pearson on the *raw normalized* amplitude already ignores `s` and `c`, so
for the Sniper D-CFR adds only tilt tolerance, at the price of a
first-difference high-pass that roughly doubles per-subcarrier noise variance
(`channel_filter_en = false` in `firmware/anchor/main/sniffer.c`, so adjacent
estimates are independent). The #29 ablation should therefore include "raw
normalized amplitude + Pearson".

## 2. ESP32 CSI facts

Confirmed in ESP-IDF (`components/esp_wifi/include/local/esp_wifi_types_native.h`,
master):
`wifi_csi_config_t { lltf_en, htltf_en, stbc_htltf2_en, ltf_merge_en, channel_filter_en, manu_scale, shift, dump_ack_en }`,
`wifi_csi_info_t { rx_ctrl, mac[6], dmac[6], first_word_invalid, *buf, len, ... }`,
and `wifi_pkt_rx_ctrl_t.rssi` ("signed rssi:8 ... unit: dBm") plus
`noise_floor` (dBm) and `sig_mode`. The Wi-Fi driver guide
(docs.espressif.com/projects/esp-idf/en/latest/esp32/api-guides/wifi-driver/wifi-vendor-features.html,
"Wi-Fi Channel State Information") gives LLTF at 20 MHz/no secondary channel
as sub-carrier index "0~31, -32~-1", 128 bytes, "imaginary part followed by
real part", and states "If first_word_invalid ... the first four bytes of CSI
data is invalid due to a hardware limitation in ESP32". Amplitude scale caveat: `manu_scale` doc string, "manually
scale the CSI data by left shifting or automatically scale ... false:
automatically" — the buffer is auto-scaled per packet, which is the primary
evidence for per-packet normalization; newer chips export `agc_gain`/`fft_gain` per record (espressif/esp-csi).
Single antenna is a chip fact (one `ant` bit in `rx_ctrl`, no per-antenna
CSI streams). **Not reached:** a peer-reviewed primary source stating ESP32
per-packet phase is unusable; Espressif's own esp-crab example exists to add
"radio frequency phase synchronization" hardware for phase work, which is
circumstantial support for amplitude-only.

## 3. k-NN baseline

RADAR (Bahl & Padmanabhan, INFOCOM 2000, doi:10.1109/INFCOM.2000.832252;
microsoft.com/.../infocom2000.pdf) is the origin of k-NNSS averaging: "for
small k, averaging has some benefit though not very significant ... For large
k, accuracy degrades rapidly" (§4.1.2), and Fig. 5 sweeps k=1..10. Small k
(2–4) is the standard baseline; k=3 is fine. Inverse-distance weighting is
the later WKNN convention (not in RADAR; Torres-Sospedra et al., ESWA 2015,
doi:10.1016/j.eswa.2015.08.013 analyse k and metrics — *not reached*, do not
cite specifics). No primary source recommends equal-weight concatenation of
heterogeneous blocks, and the arithmetic argues against it as written: per
window the RSSI block has 4 dimensions and the D-CFR block ~4×50 = 200, so
per-dimension z-scoring with "equal block weight" lets D-CFR dominate the
Euclidean distance ~50:1. Also "z-scored RSSI" is ambiguous: z-scoring each
feature over the Radio map does *not* remove a device gain offset; z-scoring
the 4 anchor RSSIs within a window does (it is the dB analogue of Kjærgaard's
ratio fingerprints, item 7). The ADR's consequence "device heterogeneity is
addressed by z-scoring RSSI" only holds for the within-window variant.

## 4. MDN scout

Bishop, *Mixture Density Networks*, NCRG/94/004 (Aston, 1994;
publications.aston.ac.uk/id/eprint/373): kernels are Gaussian with one
variance per kernel (isotropic, Eq. 23, with components "statistically
independent within each component"), mixing coefficients via softmax (Eq.
25), variances via `exp` of network outputs (Eq. 26), NLL loss. Diagonal
(x,y) Gaussians are a small generalization Bishop allows. Bishop also warns
that the fitted mapping is "more sensitive to network architecture, weight
initialization, etc." with "the network often finding significantly poorer
solutions" (§ inverse problem), and contrasts the conditional mean with "the
centre of the most probable kernel" because the mean of a multimodal
mixture can sit between modes. Localization precedent: Qian, Lauri, Gechter,
*Convolutional Mixture Density RNN ... WiFi Fingerprints*, arXiv:1911.09344
(2019), an MDN over RSSI with K=30 chosen by sweep. Pitfalls for the ADR: the
fallback estimate "bbox centre" inherits the between-modes problem; use the
most probable kernel's mean (Bishop) or the mixture mode instead, and record
a σ floor / log-sum-exp in the NLL (numerical, no citation needed).

## 5. Particle filter with w = ∏ exp(ρ/σ)

FILA (Wu et al., Eq. 10–11) already fuses per-AP Pearson correlations of
normalized CSI spectra as a product over APs and normalizes it into a
probability over reference points, so "∏ over anchors of a function of ρ" has
a direct precedent in the thesis's own citation. The exponentiated form is
the ADR's design choice: ∏ exp(ρ_k/σ) = exp(Σρ_k/σ), a softmax over the
summed correlation with temperature σ, bounded because ρ ∈ [−1, 1]. No CSI
fingerprint PF paper using exactly this weight was found; say so in the
thesis and cite FILA for the product-of-ρ idea.

## 6. Thresholds (ρ ≥ 0.6, −80 dBm, ≥ 3 Records)

No primary source gives a Pearson threshold for CSI fingerprints or an ESP32
RSSI reliability floor; the ADR correctly presents them as anchored to the
2026-08-28 capture. Two facts do bear on them. (a) ESP-IDF exposes
`rx_ctrl.noise_floor` (dBm) alongside `rssi`, so an SNR floor
(`rssi − noise_floor`) is available at no cost and transfers across rooms
better than an absolute −80 dBm. (b) FILA (§5.2) keeps the K = 3 most reliable APs, the same shape as
`min_anchors = 3`. Ghany et al.
2020 (`ghany2020robustness`, doi:10.1109/VTC2020-Fall49728.2020.9348854)
is the bib's CSI-vs-RSSI robustness source; *not reached* here, so do not
attach specific numbers to it.

## 7. Protocol (ADR-0003)

Horus (Youssef & Agrawala, MobiSys 2005, usenix.org/legacy/event/mobisys05/
tech/full_papers/youssef/youssef.pdf, §7.1) is the closest precedent and
matches the ADR on every point: training points "1.52 meters (5 feet) apart"
(2.13 m on the second testbed); "100 test locations ... none of them
coincide with a training point"; the test set "collected by different persons
on different days and times of day than the training set", justified as
"realistic ... should, if anything, decrease the measured accuracy". RADAR
used 70 points on a 43.5×22.5 m floor (coarser than 1 m) and leave-one-out
over physical points; its TR (MSR-TR-2000-12, §6.2) documents drift ("a Radio
Map created at any one particular time may not accurately reflect the
environment at a different time", one body ≈ 3.5 dB) and answers it with
multiple radio maps. FILA's testbeds were 3×4 m and 5×8 m, so ~1 m spacing is in line with
CSI-era room-scale work. Device
diversity: Haeberlen et al., MobiCom 2004, doi:10.1145/1023720.1023728
(linear mapping between cards); Kjærgaard & Munk, PerCom 2008,
doi:10.1109/PERCOM.2008.75 and Kjærgaard, PMC 7(1) 2011,
doi:10.1016/j.pmcj.2010.04.005 (hyperbolic fingerprints = RSS ratios, i.e.
dB differences, which cancel per-device gain). The ADR's single cross-device
Trial is a measurement, not a mitigation; citing these makes the gap
interpretable and points at the within-window z-score as the mitigation.

## Recommended ADR changes

- [ ] ADR-0002 D-CFR paragraph: replace "removes ... linear tilt" with
      "converts a linear tilt into a constant, which Pearson ρ ignores";
      state that the k-NN baseline is not tilt-invariant unless the D-CFR
      block is mean-centred per anchor; drop `wu2012csi` as the D-CFR source
      (it owns normalization + Pearson, not differencing) — feed into #31.
- [ ] ADR-0002 ablation (#29): add "raw normalized amplitude + Pearson" as an
      arm, since it isolates what differencing adds beyond Pearson.
- [ ] ADR-0002 k-NN: define "z-scored" (per feature over the Radio map vs
      per window across anchors) and define "equal block weight" as equal
      total weight (scale each block by 1/√dim), otherwise D-CFR dominates
      ~50:1. Cite RADAR for k≈3.
- [ ] ADR-0002 MDN: fallback point estimate = most probable kernel mean (or
      mixture mode), not bbox centre; cite Bishop 1994 and Qian 2019.
- [ ] ADR-0002 PF: cite FILA Eq. 10–11 for product-of-ρ fusion; label
      `exp(ρ/σ)` as this work's surrogate with no direct precedent.
- [ ] ADR-0002 floor: express as SNR using `rx_ctrl.noise_floor` (already in
      ESP-IDF) or record why absolute dBm is kept; requires the firmware to
      emit `noise_floor` in the Record.
- [ ] ADR-0003: cite Horus for off-grid held-out points and different-day
      test sets, RADAR TR for drift, Haeberlen 2004 / Kjærgaard 2008, 2011
      for device heterogeneity; add these to `thesis/references.bib`.
- [ ] Firmware/ADR: note `channel_filter_en = false` and auto-scaling
      (`manu_scale = false`) as the documented reasons for per-packet
      normalization and independent adjacent subcarriers.
