# 2026-09-18 — First Wireless Anchor → Relay → Gateway Capture on the MP700

## Summary

First end-to-end capture over the shipped wireless topology with the Pi out
of the loop: one Anchor (A1) → ESP-NOW → Relay → WiFi UDP → laptop Gateway,
using a TP-Link MP700 pocket WiFi as the trial network. `make listen` landed
`data/A1_20260918_032204.csv`: **6108 CSI Records in 3 min 22 s (~30/s)**,
channel 11, RSSI −21 to −85 dBm. Two hardware problems were cleared on the way
(esptool flash failure and garbled serial output — both fixed by dropping
from 921600 to 115200, now the repo default). One design finding: 98 % of the
sniffed frames were the **Relay's own UDP transmissions**, so the Anchor is
currently recording the Relay as a target.

## Log

- Flashing `relay.ino` at upload speed 921600 failed after the stub loaded:
  `A fatal error occurred: Unable to verify flash chip connection (No more
  data to read from the serial port)`. Sketch compiled fine (68 % flash,
  14 % RAM). Board reports `ESP32-D0WD-V3`, 40 MHz crystal, MAC
  `68:fe:71:fa:df:fc`.
- Serial Monitor at 921600 showed only junk. Readable at 115200 → the
  board's USB-serial bridge (CH340-class clone) can't hold 921600.
- Switched the live path to 115200 everywhere: `relay.ino` `Serial.begin`,
  `anchor_arduino_wireless.ino` `SERIAL_BAUD`, `uart_listener_2.py --baud`
  default, and the flash/monitor numbers in both READMEs. Legacy
  `anchor_arduino/` sketches and `gateway_logger.py` left at 921600.
- Pointed `anchor_arduino_wireless.ino` `relay_mac` at the Relay's real
  base MAC `68:fe:71:fa:df:fc` (was a stale `3c:8a:1f:9a:66:8c`). Note the
  ESP-NOW peer address is the STA/base MAC that esptool prints at flash time,
  so it can be read off the upload log before the Relay even boots.
- Configured the MP700: fixed 2.4 GHz channel 11 (matches
  `WIFI_CHANNEL 11` on the Anchor), SSID `TP-Link_40F1`, subnet
  `192.168.0.0/24`. Laptop given static `192.168.0.197` = `GATEWAY_IP`.
  `relay.ino` CONFIG block edited locally to these values — **not committed**;
  the repo keeps the `trial-network` placeholders.
- Reflashed Relay and Anchor at 115200. Relay printed the MAC banner and
  `INFO,wifi_connected,ip=…` on the MP700.
- `make listen` → `new anchor A1 -> data/A1_20260918_032204.csv`, line
  counter climbing every 5 s.
- Capture contents (`tail -n +2 | cut -d, -f4` on the quoted line):

  | Source MAC | Frames | Note |
  |---|---|---|
  | `68:fe:71:fa:df:fc` | 5977 | the Relay itself (its UDP forwarding traffic) |
  | `8c:90:2d:19:40:f1` | 130 | the MP700 access point (beacons) |
  | `4a:cf:6e:3e:5b:93` | 1 | randomized-MAC client, one frame |

  All 6108 Records are `CSI,`; the wireless Anchor sketch emits no `STAT`
  lines (only the legacy serial `anchor_arduino` does), so the per-anchor
  `pkts_seen / csi_cb_count / dropped` counters are absent on this path.
  `HEARTBEAT,` lines from the Relay are counted by the listener and not
  written to the Capture.

## Issues & Fixes

| Problem | Cause | Fix |
|---|---|---|
| esptool `Unable to verify flash chip connection` at 921600 | USB-serial bridge drops bytes at that rate | Upload speed 115200 (hold BOOT if `Connecting...` stalls) |
| Serial Monitor junk at 921600 | Same bridge limit | `Serial.begin(115200)` in `relay.ino`; repo standardized on 115200 |
| Anchor sent to nowhere | Stale `relay_mac` from a previous Relay board | Set to the MAC esptool printed for the Relay |
| **Anchor records the Relay** | Relay's UDP forwarding is itself 802.11 traffic on the sniff channel; every forwarded Record produces a new frame for the Anchor to sniff, so the Relay dominates the Capture (98 %) and burns ESP-NOW airtime | Open. Options: drop frames whose source MAC == `relay_mac` inside the Anchor's CSI callback (cheapest, one compare); or rely on `gateway --devices` / `--mac-filter` at preprocessing time (works but wastes the radio link). Recommend the firmware filter. |
| Serial fallback throughput | 115200 caps `make capture` at ~36 CSI lines/s (see `firmware/README.md` bandwidth table) | Acceptable — the wireless path is the primary link and serial on the Relay is only a mirror. Raise `relay.ino` + `--baud` to 460800 together if serial capture ever needs more. |

## Setup / Reproduce

1. MP700 admin (`http://192.168.0.1`): 2.4 GHz, fixed channel 11.
2. Laptop on `TP-Link_40F1`, IPv4 manual `192.168.0.197/24`, router
   `192.168.0.1`.
3. `relay.ino` CONFIG: `WIFI_SSID`/`WIFI_PASSWORD` = the MP700's,
   `GATEWAY_IP "192.168.0.197"`, port 5555. Flash at upload speed 115200.
   Serial Monitor 115200 → note MAC banner, wait for `INFO,wifi_connected`.
   Close the monitor.
4. `anchor_arduino_wireless.ino`: `ANCHOR_ID "A1"`, `relay_mac` = Relay MAC,
   `WIFI_CHANNEL 11`. Flash at 115200.
5. `make listen`. Allow Python through the macOS firewall if prompted.
6. Traffic source: a phone on the MP700 streaming video, or
   `ping -i 0.05 192.168.0.1` from the laptop.
7. `head data/A1_*.csv`; MAC breakdown:
   `tail -n +2 data/A1_*.csv | awk -F'"' '{print $2}' | cut -d, -f4 | sort | uniq -c | sort -rn`
