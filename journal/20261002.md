# 2026-10-02

## Summary

Built the spatial simulator for #25: a Trial layout file
(`layouts/techhub_default.yaml`, placeholder 8 × 6 m room) and
`gateway/sim.py`, which writes calibration and test sessions as per-Trial
Capture directories plus `ground_truth.json`. `gateway.preprocess` consumes
them unchanged. The CSI ray model departs from the issue's
"first-order reflections" spec, for the reasons below.

## Log

- Extracted the logger-format writer from `gateway/synth.py` into
  `write_capture()` so the old synthetic generator and the new simulator
  share one wire-format writer. `tests/test_end_to_end.py` is unchanged and passes.
- Implemented RSSI (log-distance + per-(Anchor, position) shadowing + jitter),
  the image-source CSI model, steady/sporadic transmit schedules, per-device
  nuisance (TX offset, gain, tilt), sessions, CLI and `make sim`.
- Tests in `tests/test_sim.py` cover every acceptance criterion of #25.

## Issues & Fixes

- **First-order reflections give flat CSI.** In an 8 × 6 m room the direct path
  plus four wall images add < 1 ripple across the 20 MHz band. Measured with
  20 noisy packets per window, same-spot D-CFR stability was ≈ 0.1, so
  the Sniper's 0.6 threshold (ADR-0002) would never pass on simulated data.
  Raising to `reflection_order: 4`, `wall_reflection: 0.8` gives ≈ 0.6–0.64
  after the real preprocess, close to the ≈ 0.75 measured on the −65 dBm
  device in the 2026-08-28 capture. `reflection_order: 1` remains available.
- **Baseband-only phase makes every fingerprint identical** (ρ ≈ 0.99 between
  any two grid points), and the real carrier phase decorrelates within ~6 cm.
  Each path's phase is therefore taken at an effective wavelength
  `phase_wavelength_m: 8`. After preprocessing, A1 fingerprints correlate
  ρ ≈ 0.54 between neighbouring Reference points and ≈ −0.05 at ≥ 4 m.
  This is a modelling knob, not physics, and the thesis should say so if it
  quotes simulated results.

## Setup / Reproduce

```sh

uv run python -m gateway --in sim_data/calibration/R01 --out out/r01.jsonl --summary
uv run python -m gateway.sim --out sim_data --session test --target phone   # cross-device Trial
```

The Beacon's sufficient-window rate is 100 % in all 58 Trials; every Test Trial has 40
windows.

# 2026-10-02 (cont.) — #26 Radio map, harness, k-NN baseline

## Summary

The first end-to-end accuracy number on simulated data. `make eval-baseline`
runs sim → preprocess calibration → Radio map → preprocess test → k-NN
(ADR-0002: k = 3, IDW, within-window z-scored RSSI + mean-centred D-CFR,
equal block weight, floor-imputed Anchors) → per-Trial results table and
`out/eval/baseline.json`.

| run (default layout) | median | MAE | p90 | zone acc | avail |
|---|---|---|---|---|---|
| default noise | 0.87 m | 1.22 m | 2.78 m | 67 % | 100 % |
| noiseless (`layouts/noiseless.json`) | 0.54 m | 0.59 m | 0.98 m | 90 % | 100 % |

## Log

- `gateway/radiomap.py`: windows are joined to Trials by host-time overlap
  with `ground_truth.json`; only the Trial's placed device counts. Stores
  mean RSSI, median D-CFR and median raw amplitude per (Reference point,
  Anchor), plus the preprocess `_meta`.
- `gateway/knn.py`: the baseline. `estimate(window) -> (x, y) | None` is the
  interface #27/#28 plug into.
- `gateway/evaluate.py`: metrics (MAE, RMSE, median, p90, zone accuracy,
  availability, latency), per-Trial evaluation, CLI.
- Layout gained `zones`, validated to tile the room. `gateway.io.read_jsonl`
  reads windows files back.

## Issues & Fixes

- **Test positions on a zone edge.** The first zone split at y = 3 put
  P5–P7 exactly on the boundary, so their zone hit was a coin flip
  (P5 10 %, P6 0 %). The split moved to y = 3.5 and the loader now rejects
  any Test position within 0.3 m of an internal zone edge. P5 went to 95 %.
- `make help` only listed `[a-z]+` target names; widened to allow hyphens
  for `eval-baseline`.
- **Missing-Anchor imputation vs ADR-0002.** The first version imputed
  −80 dBm *before* z-scoring, so the floor shifted the mean and sd. ADR-0002
  says the z-score uses the Anchors present, so it now does, and the
  missing Anchor is placed on that scale. One refinement the ADR does not
  state: the imputed value is min(−80 dBm, weakest present reading), so a
  missing Anchor never looks stronger than a heard one. The simulator never
  drops an Anchor from a sufficient window, so the numbers above are
  unaffected; it matters for real Captures and dropout Trials.

# 2026-10-02 (cont.) — #23 per-Anchor stability score and RSSI-floor flag

## Summary

Every per-Anchor feature in the windows output now carries `stability`
(median pairwise Pearson ρ between the D-CFR vectors of the window's valid
CSI Records, null below two) and `above_floor` (smoothed window RSSI strictly
above the floor). The floor is `--rssi-floor` (default −80 dBm, ADR-0002) and
is recorded in `_meta.rssi_floor_dbm`. The summary gains an `anchor_windows`
block: above-floor count and rate, how many stability scores were undefined,
and stability p10/p25/p50/p75/p90. These are the per-Anchor inputs to the
fallback rule that #28 implements.

## Log

- `gateway/csi.py`: `dcfr_stability()`; `valid_spectra()` replaces
  `process_window_csi()` so the per-Record spectra feed both the median
  spectrum and the stability score.
- `gateway/features.py`, `records.py`, `io.py`, `preprocess.py`: fields,
  output, summary, CLI flag and `_meta` key.
- Tests: `tests/test_features.py` (new), plus cases in `test_csi.py` and
  `test_end_to_end.py`. `make test` → 110 passed.

## Issues & Fixes

- **Floor boundary.** ADR-0002 says "above the floor"; confirmed with the
  user as strict, so −80.0 dBm at a −80 dBm floor is *not* above it.
- **Zero-variance D-CFR.** Pearson against a constant vector is NaN and would
  have been written to the JSONL as `NaN` (invalid JSON). Those pairs are
  skipped; if no pair is defined the score is null.
- **Not run on a real Capture.** The 2026-08-28 capture is in the Pi-era
  10-column format, which the parser cannot read until #24. The new code only
  reads parsed `CsiRecord`s, so it needs no change for real Captures.

## Setup / Reproduce

```sh

uv run python -m gateway.preprocess --in /tmp/sim/test/P1 --out /tmp/p1.jsonl --summary
```

# 2026-10-02 (cont.) — #24 part 1 legacy Capture reader; #27 MDN Scout

Both were built in parallel git worktrees, reviewed on two axes, and then
merged into `main`. `make test` → 125 passed.

## Summary

- **#24 part 1.** `gateway/parser.py` works out the Capture format from
  the header. It reads the Pi-era 10-column format (128 raw I/Q values,
  uppercase MACs, no sig_mode or timestamp_us) into the same `CsiRecord`s
  as the logger format. `live_csi_dashboard.py` tails files from their
  end and never sees the header, so it recognises legacy rows by their
  width. `make replay` now plots the 2026-08-28 capture. A 200-row excerpt
  of that capture, with MACs anonymised, is the test fixture. Part 2 (the
  characterization script and noise JSON) is still open.
- **#27 MDN Scout.** `gateway/scout.py` is a PyTorch MDN.
  - Input is z-scored RSSI plus a presence mask. Output is K = 3 diagonal
    Gaussians.
  - The 95 % bbox comes from the densest 95 % of mixture samples. The
    fallback estimate is the mean of the most probable kernel.
  - Torch is an optional `scout` extra. `make eval-scout` reports the
    Scout next to k-NN.

## Results (`make eval-scout`, default layout, seed 42)

```
localizer    avail    MAE  median    p90  zone acc  bbox hit  bbox area  ms/win
k-NN          100%   1.22    0.87   2.78       67%         -          -   0.046
Scout         100%   1.16    1.08   1.92       70%      100%        50%   1.004
```

Training takes about 5 s on CPU. The Scout has a better p90 than k-NN and
a worse median. P2, P7 and P9 have zone accuracy of 10 %, 0 % and 0 %. P9's
box covers 84 % of the room.

## Issues & Fixes

- **The spec contradicts itself on the fallback estimate.** #27 and
  ADR-0002's Fallback rule said "bbox centre". ADR-0002's Scout paragraph
  says the mean of the most probable kernel, and rejects the centre
  because a multimodal mixture's centre can land between modes. The user
  chose the kernel mean, and the Fallback-rule sentence and CONTEXT.md
  now agree with it.
- **Bbox area target.** "Well below the full room" had no number. The box
  is about 50 % of the room. Lowering the augmentation noise shrank it to
  44 %, but the hit-rate fell to about 80 %. The user fixed the threshold at
  < 60 % and the area is reported as a result. The width is set by the
  simulator's 3 dB shadowing. The main kernel's σ is about 1–1.5 m.
- **What the augmentation does.** Within-window z-scoring cancels any
  change that is affine and shared by all Anchors: device gain, and a
  common change of path-loss exponent. The augmentation therefore uses
  per-Anchor noise (4.2 dB), a ±6 dB device offset, and a 10 % chance of
  dropping one Anchor. A per-Anchor exponent jitter would be a more
  literal reading of "path-loss perturbation". It has not been tried.
- **Bbox and the mixture mean.** The densest region of a multimodal
  mixture need not contain its mean, so the box is widened to take the
  mean in. This is a deliberate departure from a pure 95 % box, and the
  docstring says so.
- **The dashboard was not reading legacy files for free.** The #24
  comment said it would. It parsed rows itself, so it now calls
  `parser.legacy_row_to_line`.
- **`make capture` is broken against current firmware** (#39). The
  serial listener writes legacy columns, but the 9-field firmware lines
  no longer fit them. The parser counts those rows as malformed rather
  than misreading them.

# 2026-10-02 (cont.) — #28 Sniper, fallback rule and the proposed pipeline

## Summary

`gateway/sniper.py` adds the Sniper (a D-CFR particle filter inside the
Scout's bbox), the ADR-0002 fallback rule, and `ProposedLocalizer`, which
gives one estimate and one Mode per window. `make eval` runs k-NN, the
Scout and the proposed pipeline on the simulated Trials and prints one
comparison table, the fallback rate and the latency. On the held-out
`make sim` session (seed 42) the proposed pipeline gets MAE 0.47 m,
median 0.34 m and p90 0.82 m, against the Scout's 1.16 / 1.08 / 1.92 m and
k-NN's 1.22 / 0.87 / 2.78 m. Zone accuracy is 89 % (Scout 70 %, k-NN 67 %),
the fallback rate is 2 %, and latency is 1.57 ms/win (k-NN 0.05 ms).

## Log

- The fallback rule counts *Sniper-ready* Anchors: ≥ 3 valid CSI Records,
  stability ≥ threshold, `above_floor`. The particle weights use only the
  ready Anchors. An Anchor that is not ready, or whose Reference point has
  no stored D-CFR, adds a factor of 1, so it neither penalizes nor vetoes.
- Particle filter: uniform start in the bbox, then nearest-Reference-point
  lookup, `Σ ρ/σ` log-weights, weighted-centroid estimate and systematic
  resampling. Across a Trial's windows the particles carry over with
  Gaussian jitter. Particles that leave the new bbox are redrawn inside
  it. The harness now calls `reset()` at each Trial start and records
  `mode` → `fallback_rate`. A fallback window leaves the particles as they
  are.
- σ and the jitter were tuned on a separate validation sim (calibration
  seed 7, test seed 8), not on the seed-42 session `make eval` reports.
  At σ ≤ 0.5 the particles lock onto a wrong Reference point after one
  noisy window, and at σ ≥ 4 they stop converging. The pick is σ = 2 with
  0.3 m jitter (validation MAE 0.38 m).
- Fallback estimate = the mean of the Scout's most probable kernel
  (ADR-0002, CONTEXT.md), not the bbox centre the #28 issue text says.
  The earlier entry above records why.

## Issues & Fixes

- **No simulated window is Sniper-ready at the 0.6 threshold.** This is the
  open decision noted above. Lowering `csi_noise`, shortening
  `phase_wavelength_m` or raising `wall_reflection` gets at most 10–20 %
  of windows ready. The Anchor nearest the target sees an almost flat
  simulated spectrum (D-CFR sd ≈ 0.1 against a noise-difference sd of
  1.1), so its stability stays near 0 regardless. Readiness also goes
  whole-Trial at a time (10 % steps), so any positive threshold only drops
  Test positions. Decision: keep 0.6 as the default (ADR-0002, sized on
  real Captures), add `--min-stability`, and have `make eval` pass 0 on
  simulated data. The 0.6 gate itself is tested on synthetic windows.

## Setup / Reproduce

```sh
make eval                                         # out/eval/proposed.json
uv run --extra scout python -m gateway.sniper --sigma 1 --min-stability 0.6
```
